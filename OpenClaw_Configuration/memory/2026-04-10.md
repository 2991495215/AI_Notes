# 2026-04-10

## 会话记录
- 发现本轮在“创建新 skill”任务中出现明显执行阻塞：已口头承诺开始执行，但后续连续停留在 skill 选择、补充阅读、结构犹豫阶段，未立即进入真实写入。
- 用户多次明确反馈“卡住不说话”“别停”，说明问题不在环境，而在执行纪律、状态汇报和规则收敛失败。

## 修正规则（立即生效）
- 对明确产物型任务（创建/修改文件、封装 skill、写脚本、改配置），一旦表述“开始执行/开始修改”，下一动作必须是 `write` / `edit` / `exec` 之一，禁止继续补读多个 skill。
- 多个 skill 看起来都相关时，只选最直接支持当前产物的那一个；不再为“理论上更完整”而扩读。
- 若答应执行后 30–60 秒内仍未产生真实写入或命令执行，必须先向用户明确汇报：还没开始落地、当前卡点、接下来切换成的最简执行路径。
- 低风险任务不允许把谨慎用在命名、结构美化、补充阅读上；先做最小可用版本，再优化。

## 影响
- 这条修正规则后续适用于 skill 创建、脚本编写、文件整理、原型搭建等所有明确产物型任务。
