# 1. GenericAgent 的性能需求
## 特征
它的目标是：

- 用很小的核心代码
- 很少的原子工具
- 让 agent 自己探索
- 再把路径沉淀成 skill

### 优点
**平时很省。**

因为它的核心哲学就是：

- 少上下文
- 少框架负担
- 少中间层
- 少 orchestration

如果 skill 命中了，后续执行会很轻。

### 主要开销在哪
不是框架本身，而是**任务第一次探索时的执行成本**：

- 多次推理
- 多次试错
- 写脚本
- 装依赖
- 调浏览器/ADB
- 屏幕识别或系统控制

也就是说：

> **它的“框架空载成本”低，但“首次任务探索成本”可能高。**

### 适合的机器
- 普通桌面
- 轻量 VPS + 外部 API
- 有 GUI / 浏览器环境的本机

如果本地要跑视觉、ADB、浏览器注入，资源主要花在这些执行侧，不在 agent 框架本身。

---

# 2. Hermes 的性能需求
我这里按你说的 Hermes 气质来理解：  
**长期协作型、记忆更重、策略层更强、不是纯一次性执行器。**

## 特征
Hermes 一般会比 GenericAgent 多这些负担：

- 更稳定的人格 / 角色层
- 更持续的会话状态
- 更重的记忆组织
- 更强的长期任务延续
- 更多“判断一致性”要求

### 性能开销表现
它通常不是最吃“原子执行”，而是更吃：

- **上下文管理**
- **记忆检索**
- **长期状态维护**
- **任务规划质量**
- **跨轮一致性**

换句话说：

> **Hermes 比 GenericAgent 更像“脑力负担重”，而不是“手脚负担重”。**

### 资源画像
如果一个系统越强调：

- 长期记忆
- 个体性
- 经验沉淀
- 协作身份稳定

那它通常越需要：

- 更好的记忆索引
- 更稳的上下文裁剪
- 更强的状态管理
- 更好的模型质量

所以 Hermes 往往对**模型质量和记忆设计**更敏感。  
不是说一定更费硬件，而是更费“认知预算”。

---

# 3. OpenClaw 的性能需求
## 特征
OpenClaw 更像平台：

- 工具多
- 通道多
- session 多
- 节点多
- cron / 消息 / browser / subagent / gateway 都在体系里
- 还有配置、路由、跨会话、外部集成

### 它吃的是什么
它吃的是**系统复杂度**。

不是单纯说它推理比别人多，而是：

- 常驻服务开销更高
- 模块更多
- 维护面更广
- 状态更多
- 集成点更多
- 运行链路更长

所以它的“性能需求”更多表现在：

#### 1) 工程资源
- 部署更重
- 排障更复杂
- 配置项更多
- 链路更长

#### 2) 运行时资源
- 常驻进程
- 消息路由
- 浏览器 / 节点 / 会话调度
- 多工具调用与上下文管理

#### 3) 模型成本
如果你真把它当长期全能助手用，  
因为入口多、任务多、并发多，**总体 token 消耗很容易高于极简框架**。

# 4. 把三者拆成几个维度看

## A. 空载开销
就是“啥都不干时，系统自己有多重”。

- **GenericAgent：最低**
- **Hermes：中**
- **OpenClaw：最高**

因为 GenericAgent 就是奔着最小内核去的。  
OpenClaw 则天然不是轻空载产品，它是平台型。

---

## B. 首次完成新任务的成本
就是第一次没经验时，谁更费。

- **GenericAgent：可能高**
- **Hermes：中高**
- **OpenClaw：看编排方式，通常中**

GenericAgent 因为强调自己摸索、自己长 skill，第一次最容易烧 token 和时间。  
Hermes 如果也强调长期学习，那首次成本也不会低。  
OpenClaw 如果现成工具多，很多任务第一次反而可能更快，不必“野路子探索”。

---

## C. 长期复用后的成本
就是同类任务做第 N 次。

- **GenericAgent：最低潜力最大**
- **Hermes：也能很低，但取决于记忆命中质量**
- **OpenClaw：通常仍高于前两者**

因为 GenericAgent 核心卖点就是“把路径固化成 skill”。  
一旦沉淀得好，复用会很便宜。  
OpenClaw 因为体系更重，就算复用也还有平台层负担。

---

## D. 对模型质量的依赖
- **GenericAgent：高**
- **Hermes：很高**
- **OpenClaw：中到高**

为什么？

### GenericAgent
因为它把很多事情压给 agent 自己探索。  
模型差一点，探索路径会变歪，写出的 skill 也会歪。

### Hermes
更依赖高质量推理和长期一致性。  
差模型会导致人格漂移、记忆污染、长期协作质量下降。

### OpenClaw
有更多系统工具能托底，  
有时可以靠工具链减少纯推理负担，  
但复杂任务下仍然吃模型质量。

---

## E. 对硬件/本地环境的依赖
- **GenericAgent：最高**
- **OpenClaw：中**
- **Hermes：看实现，通常中低**

原因很简单：

GenericAgent 很多价值来自：

- 浏览器接管
- 键鼠
- 视觉
- ADB
- 本机脚本

所以它对**本地可执行环境**特别依赖。  
Hermes 如果偏认知和协作层，就没那么强依赖物理执行环境。  
OpenClaw介于中间，它也能碰浏览器、节点、外部工具，但不是必须全压在本机 GUI 上。

---

## F. 运维复杂度
- **GenericAgent：低到中**
- **Hermes：中**
- **OpenClaw：高**

GenericAgent 核心小，部署轻。  
但后期如果 skill 树膨胀、脚本乱长，维护会从低变中。  
OpenClaw 一开始就是体系化平台，运维复杂度天然更高。

- 对模型质量要求高
- 更像“长期脑力伴侣”
