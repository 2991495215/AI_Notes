## 5. 权限层
这是 Claude Code 真正和普通“AI CLI”拉开距离的地方。

### Exhen
你能从 `Tool.ts` 和权限相关文件看出：
- 有显式 `ToolPermissionContext`
- 有 mode-based permission system
- 子代理可以 `bubble` 权限
- hook、tool 自检、全局模式会叠加决策

Alejandro 总结的 7 种权限模式很关键：
- bypassPermissions
- dontAsk
- auto
- acceptEdits
- default
- plan
- bubble

这说明它不是“每个工具自己随便判断”，而是一个**策略系统**。

### Ultraworkers
核心文件：
- `runtime/src/permission_enforcer.rs`

它的实现目前更保守，也更工程化：
- `PermissionEnforcer`
- `EnforcementResult`
- `check(tool_name, input)`
- `check_file_write(path, workspace_root)`
- `check_bash(command)`

当前形态比较像：
> **把 Claude Code 成熟的权限体系，先收敛成可维护的 runtime enforcement layer。**

它现在的强项：
- file write boundary
- bash mutability heuristics
- mode-based deny/allow

弱点也明显：
- 还没到 Exhen 那种复杂 hook + auto classifier + bubble escalation 的成熟程度

### 统一结论
